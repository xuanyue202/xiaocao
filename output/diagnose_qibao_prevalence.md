## Decision

- median(active_main) = **0** / day, sum = **18**
- median(active_relax_jssb=150) = 0 / day
- median(active_relax_pct=5) = 0 / day
- median(active_relax_both) = 0 / day

**真正的瓶颈不是 pool 也不是 pct，是 jssb scale 本身**。诊断过程：

- `0 < pct ≤ 4` median = 60 / day（candidates 充足）
- `jssb ≥ 200` median = 0 / day，sum 只有 76 stock-day across 159 天 × ~277 stocks
- 全 cache jssb 分布：p50=0.05, p90=2.36, **p99=60.60**, max=1629
- 对比 xcjw 分布：p50=94.6, p90=244, p99=624, max=1640 — **scale 完全不同**

也就是说 STRONG_JW=200 在 jssb 上是 p99.7+ 的极端尾部，但在 xcjw 上是 p83。两种可能：

1. **rule 的 jssb 阈值 200 实际本意是 xcjw=200** —— calibration 从 xcjw 抄到 jssb 没改
2. **EOD cache 里 jssb 是 decayed value**：jssb 是 9:25-9:35 集合竞价 + 早盘的净申报指标，盘后回落到极低或 0；rule 假设 intraday 高峰，EOD 数据无法 surface

不管是 (1) 还是 (2)，结论一致：**红盘起爆主攻 mode 在 EOD backtest 框架下结构性失灵**，不是 sample 不足，是这个 mode 的 prediction frame 本身就是 intraday，EOD 截面拿不到。这与报告 §4 的 "1-day backtest vs 多日持仓 prediction frame mismatch" 是同一个根：信号 emission 也得对的预测窗口里取。

下一步分两条路：
- 短期 (EOD frame)：把 jssb 阈值 calibration 到实际 distribution（如 jssb p95=7.84，可改 STRONG_JW=10），重跑看 active count 是否提升
- 中期 (Phase C 盘中)：把 红盘起爆 mode 移到 9:30-9:35 intraday 信号生成层，用 9:31 实时 jssb 而不是 EOD 残值

后者才是真 fix。前者只是看 EOD 残值能不能挤出有用信号——大概率不能。
