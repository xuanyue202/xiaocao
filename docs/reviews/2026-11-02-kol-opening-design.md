## 目标与边界

目标是产生可追溯的选择差异，而不是增加流程。判断应该回答环境适用、模式方向、
候选风险与仓位条件；每次解释基线选择、KOL实际改变、未采用及原因。可用率、耗时、
采用率与有费用/成交依据的配对结果分别衡量，工程成功不能证明收益改善。

当前接口已有四种实际作用：买入缩放、精确代码跳过、可卖持仓退出，以及小草明确
模式跟随。最后一项通过独立复核的 v2 在原冻结池内优先选择模式，可有条件恢复
COLD；UNKNOWN、资金、行情、账户及订单守门保持。这不是一般赛道评分或任意选股。
既有 book_b_workflow 已记录 baseline_codes、strategy_codes、mode_follow_bindings、
逐行原因和 final_plan；本次沿用这些证据，不建立第二本判断账。

下一步产品取向建议：在原冻结池内，让已验证的环境/模式/赛道条件参与候选优先级，
同时保留上述硬门；使用明确来源和标准资产/模式映射，不按关键词打行业分。
通用候选重排、赛道权重或新候选生成属于新的策略接口，应明确其适用池、冲突处理、
未映射处置及配对研究协议后再启用。本次性能修复不把这项设计建议伪装成已部署。

## 已实现的优化

1. `context --decision-sources --report-id ID --read-report-id ID --summary` 只加载准确
   引用正文，保留全部已登记作者及其完整 writer 发布语义；没有 latest-N 截断，
   也不把历史原观察时间伪装为新远端验证时间。相关当前报告逐个检查远端头；
   头与完整 manifest 相同则本地校验并复用不可变记录，有变化才读变化后的完整来源。
2. `kol_trading_decision.py context-check --context FILE` 在准备封存前查完整性和
   本地来源闭包。context_ready只证明已知来源前提；最终判断、独立复核和发布
   时的远端当前性仍分别必需。旧准备与旧发布回执不改写。
3. 发布时每个准确引用报告只读取一次当前已发布报告头，验证正文、完整manifest、
   每个复用记录的哈希和原观察时钟。评价或关系变化即使正文没变也拒绝旧上下文。
   原09:27截止、完整性门和精确已完成重试保持。

完整历史远端审计保留原入口；交易者不再把它作为一轮开盘适配的网络工作。
已知来源、作者或清单仍缺证时提早显式恢复或降级，不制造通过。
