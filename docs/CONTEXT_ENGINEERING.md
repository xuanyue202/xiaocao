# Xiaocao consumer context and loop design

## The consuming unit

A scheduled invocation needs one role, one current phase, exact owner/input and
one next legal action. Startup prompt→role guide→event-specific reference→raw
receipt is the default reading order. Shared identity/recovery/financial/delivery
procedure is in the trading automation-context reference; semantic authority
stays in Contract/source schemas, not another copied summary.

WHY: a year of dated amendments left instructions for many consumers together.
The resulting conflict is a behavioral defect even when every paragraph was once
reasonable. Shorter is not by itself better; measure the correct next action,
original authority and complete evidence, then context/time cost.

## Loop contract

Each role/phase co-locates:
1. Trigger and owner/authority; exact first command and what stops this branch.
2. Minimal current inputs, original version/hash/clock/budget and scope.
3. Action and the concrete observation proving completion of that action.
4. Incomplete/failure branch: reconcile uncertain effects or repair a dependency;
   then legal original continuation with proof of what changed.
5. Task completion, separate from process exit, with actual receipts/no-op scope.

A duplicate/hour_busy/sparse no_op ends before projection/supporting reads.
An early recoverable blocked process starts owned repair, not automatic closeout.
These are distinct loop branches; a generic 'always continue' or 'terminal means
finished' rule is wrong. Preserve original absolute budgets and irreversible
claims. Domain eligibility is never replaced by generic loop prose.

## Cohesion and low coupling

- Automation prompt: exact identity/first action, role-guide pointer, key stop,
  completion and WHY. No repeated whole financial/strategy contract or incident log.
- Role guide: ordered phase loop with event→reference→response/receipt. Read only
  current phase; source acquisition, applicability, submit and closeout differ.
- Shared procedure: ownership/evidence/recovery/notifications once; domain truth
  and values remain in the corresponding source/Contract/protocol registry.
- Detailed old automation references remain lookup contracts with compatible paths;
  current contradictions are corrected in place. Dated reviews explain provenance,
  not another instruction layer to append to every active prompt.
- Strategies: STRATEGY_CONSUMPTION.md maps actual caller and authority; it does not
  copy every threshold, substitute a label or promote a research module.

For a short list of roles, use a router rather than many unrelated new skills.
The source and applicability analyst models have different objectives and separate
configuration authorities. Never homogenize them during context cleanup.

## Leave WHY beside important choices

A meaningful rule includes scope, reason and what would justify changing it.
For example: keep original claim after a lost response, because a timeout does
not prove no effect; restore via exact readback, not a second submit. Or preserve
Paper B's first-minute HIGH because it deliberately stress-tests profitability;
fix source proof rather than lower cost to obtain a better report.

Keep the short causal reason next to the executable consumer choice. Long history,
rejected alternatives and evidence belong in the linked review/ADR, not an endless
series of dated imperatives. Code comments explain non-obvious constraints;
tests prove affected behavior, not wording, model preference or document versions.

## Versioned instructions are executable evidence

Opening preparation binds the unchanged full Contract, kol-trading-judgment and
kol-opening-preparation bytes. This refactor does not move their normative rules
behind unbound annexes. New role guides route operations; they cannot add economic
or strategy authority outside those canonical rules. Any future rule move must
bind the whole operative closure and preserve existing immutable request handling.

Semantic source packets v1/v2 keep exact reconstruction/wording for historical
readback. V1 preparation is rejected as read-only; v2 re-prepare is byte-identical.
New v3 binds semantic-analysis and routing
alongside full source contracts/profile. The analyst verifies full-file hashes,
reads all required semantic/source-specific sections and ALL source evidence to
EOF; provider/external-writer recipes stay with the executor. Reading-map changes
invalidate v3 acceptance and create distinct immutable context revisions, never
rewrite an accepted old prompt or receipt. Full-source coverage and independent
parent acceptance remain required; hashes alone cannot prove a model read them.

Packaging includes the full referenced closure and static profile/config, not
private credentials/runtime state. A missing stage guide in the fallback bundle
is a broken deployment interface even if the checkout links work. Review and
validate the actual consumed artifact/version, not only a source-file diff.

## Change and evaluate

Pin baseline, raw prompts/metadata and stable paragraph/consumer coverage before
editing. Every retired imperative maps to a current ordered action or documented
supersession; an automatic mapping count is not semantic equivalence proof.
Keep active/paused state, host/project/cwd, model/effort and cadence unchanged.
An off-host ACTIVE template is not local activation authority. API update+view
and current mirror hashes prove configuration; natural runs prove behavior.

Representative checks target emitted contracts and loop decisions: no_op stops;
preflight repair retains owner/budget; source gap cannot become NONE; warm
handoff dispatches exact args before cutoff; reviewed v2 COLD exception survives;
EOD wrappers run once; old delegation stays byte-identical; changed new reading
map invalidates admission; no extra notification/order/model writer is created.
No APP business replay or synthetic trade is permitted for a context review.

Independent Standards/Spec reviewers check the scoped diff and resolve findings.
Tests appropriate to changed wiring/protocols precede deployment; APP engineering
tests use their legal gate. Report static/fixture/production/natural evidence
separately. Shortened prompts and a green test count do not certify that all
five opening root problems are solved; the current-status review lists runtime
economic isolation, cross-day recovery and fresh-empty completion separately.
