# Morning APP session rebuild

Use only for an original waiting morning request whose compact failure reports
`recovery_kind=app_session_reset`. Current user authorization includes fixed
Founder APP restart, saved trade-account login and routine visual CAPTCHA.

1. Run `PYTHONPATH=src .venv/bin/python scripts/recover_foundersc_session.py
   --request <exact-request> --phase restart`. The port validates the original
   Automation/Thread, live runner, absolute deadline, canonical credential
   health and one durable rebuild claim. It terminates only the bound fixed
   Founder bundle and launches it once. A confirmed rejection needs a proved
   remaining budget above one; an unclassified/uncertain password never retries.
   An expired/ambiguous/locked state stops. No second restart after uncertainty.
   The request's `.session-reset-termination.json` preserves the native action
   and result, with its hash in the reset claim. An unproved termination stays
   readback-only; do not reconstruct an older missing reply or repeat the exit.
2. Fresh bootstrap/screenshot; explicitly select **交易账户** and reprove the
   same saved masked account on the login surface. Then invoke the same command
   with `--phase fill`. It claims one new password fill, stores native evidence
   and leaves the original credential fence claimed until actual readiness.
3. Read a fresh CAPTCHA image, recognize exactly four digits, enter only its
   unique field and read back the value. Run `--phase claim-login`, then press
   the unique Login once. A possible confirmation never repeats.
4. Fresh same-account native readback; run `--phase finish`. It restores ordinary
   trade capability through read-only navigation, verifies readiness and signals
   the original request once. A signal is not the original runner's ready result;
   consume its next event. Budget, order claims and UNKNOWN records remain intact.

Keep GUI steps under the shared APP session guard. If another writer owns it,
wait for that lease rather than bypassing it. Treat a known empty-password
validation notice through the existing bound native dismiss path; never blind
close unrelated windows. Saved credentials and normal CAPTCHA do not require a
new user confirmation. Missing credentials, machine permissions/account lock,
unknown actions or failed final proof remain explicit blockers.

This flow only rebuilds authentication. It neither cancels nor retries orders,
changes capital permissions, adopts manual fills, or proves a trade/settlement.

If a newly confirmed client Login has already auto-locked, finish may claim one separate saved-password unlock only for the same fresh rebuilt account/session, original request and confirmed Login attempt, with no rejection, unknown credential fence or exhausted budget. The unlock has its own linked durable claim; it never presses client Login again. Unproved unlock cannot be replayed. Final readiness still requires the account-bound ordinary trade page.

The native reset precondition includes a strictly bound same-account secondary
client-login password-error sheet. Helper 17 acknowledges only its exact known
alert button once, proves a complete modal-free graph and refreshes account/PID/
budget before quitting. A residual/new/unknown modal or incomplete AX graph
blocks termination. Preserve the structured native reset evidence; never infer
an old missing result from a later successful maintenance repair.

For explicitly user-authorized authentication-only daytime validation, use
`XIAOCAO_APP_AUTHENTICATION_TEST=1` and only `app_authentication` tests. Both
Python and native dispatch restrict this mode to authentication and read-only
navigation/query; it grants no order preparation, submission, confirmation or
cancellation authority and retains the shared APP session lease.
