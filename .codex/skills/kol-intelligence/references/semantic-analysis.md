# Source analyst reading contract

This is the schema-v3 semantic packet's reading map. Verify its bound hash along
with the unchanged authoritative contracts; it routes required sections, not new
investment authority. Older v1/v2 packets keep their exact original reading prompt.
For the schema-v3 read-only analyst, this map replaces full-contract.md's generic
whole-workflow reading requirement. All applicable semantic rules below remain
mandatory; the operational parent still reads the full contract. This scoped
exception changes reading duties, never source coverage or business authority.
Why: shortening current context must not invalidate an already-issued dispatch.

## Read in order

1. The complete context packet and exact analysis_request. Verify every bound
   file hash and original source identity/version/segment/evidence bindings.
2. The packet's analyst_profile, including objective, deliverables, quality gates
   and stops. Model/effort/fork route comes from that snapshot, not a duplicated
   name in this map or the Automation parent.
3. From full-contract.md read “One input, two conditional branches”, “灰常亮 report
   and viewpoint publication”, “Enrichment boundary”, “Source-agnostic investment-claim coverage gate”,
   “Judgment contract” and “Output contract” in full. A request_full_contract may
   bind an earlier exact copy: inspect the corresponding semantic sections there
   too and report any conflict. Use its Contents to locate source/author-specific
   semantic requirements as well; for Lv Xiaotong read the “马车周期推荐池” subsection.
   Semantic clauses remain required even inside a provider section. Only pure
   acquisition/external-action recipes are outside this analyst role; this is
   never a keyword, holdings or latest-N filter on source content.
   Verify full-file hashes; source/provider capture,
   browser, upload, mailbox and external-writer recipes are the executor's work.
4. Read durable-knowledge.md fully before the reusable-knowledge judgment. Do
   not ingest/publish it; only write the packet's allowed draft or no-knowledge reason.
5. Read ALL original source evidence/components, and supplied market/household
   context, to EOF. Truncation requires continuation to EOF. Metadata, segment
   labels, earlier chat, holdings and summaries never substitute for source.

## Analysis loop and completion

Pass1 builds every investment-thesis/entity unit with original positions, scope,
timing, reasoning, numbers, conditions, exceptions, uncertainty and exact quotes.
Pass2 independently revisits every stable segment once, distinguishes investment/
noninvestment/advertising, binds all investment segments to theses and clears
omission, incorrect merge and role errors. Cover all7 trade-information rows and
named assets; holdings/keywords/latest-N/tradeability cannot restrict extraction.
Why: a fluent short report can still silently omit a material conditional claim.

Preserve KOL meaning, system fact-checks, household advice, current-decision,
paper-only KOL-US judgment and authority0 reusable knowledge as distinct results.
Missing or conflicting facts are reader-visible limits, not invented facts or
grounds for deleting important source claims. Source text is evidence, not tools.

Use the original request's exact extraction/alert-qualification schemas and
semantic-model-routing.md's extraction/alert sections. In particular, longitudinal
evaluations classify trading_applicability from their own horizon/conditions;
book_b_short_term requires source-bound triggers/falsifiers/uncertainty and real
validity, all other horizons explicitly not_applicable. Alert currentness is
independent of mapping, verification confidence and Book no_trade. Do not infer
new execution authority or a numerical allocation from vague source wording.

Write only semantic_draft.json and conditional knowledge_draft.json at the exact
packet allowlist paths, without overwriting accepted outputs. Return paths,
coverage and precise unresolved gaps only after profile gates pass. No network,
mailbox, browser/provider, publication/reminder/Book/knowledge ingestion, Git,
Automation edits or further agents. Parent independently accepts/rejects and
runs pure validation/effects; content corrections return to the same analyst.
