# KOL 受限实时判断与统一账户风控

Status: validated and activated; scoped commit prepared

## 已确认的用户意图（2026-09-06）

用户完成 grilling 后明确回复“确认！”，授权端到端实施。外部可信 KOL
是开放信息输入，不要求每条判断先完成统计显著消融。小草优先用于短线
指标、模式及执行判断；其他已接入 KOL 用于因果逻辑、环境、主题与风险。
优先级：模拟/实盘共性 > 实盘 > 模拟。先验证一个真实样本并由主 agent
独立复核，再推广；持续前向反馈，不把工程完成说成盈利已被证明。

目标为财富增长；1500 万与 2027 年 6 月仅为远期参考，不倒推当前约三万元
账户的必达收益。新增本金、杠杆、标的资格与交易模式不在本次授权中。
用户把具体风控与评估实现交给主 agent；不把可接受大幅亏损解读为应放宽
单票止损。

## 交付设计

- 灰常亮为已发布报告事实源。现有发布登记提供 ID 发现，MCP 精确回读
  current envelope/manifest 并核对内容 hash；明确 `registry_only` 的发现范围，
  不宣称已发现远端所有未知报告。覆盖全部已登记 KOL，支持多观点、多评估。
- KOL 事实与获准的实时判断分开：独立主 agent review 绑定判断 hash；判断
  包保留来源、收到时间、适用时间、当前检查、冲突处理与失效条件。
- 共享纯消费模块只解释已核验、未过期、正确 Book/runtime 的有限判断：
  已合格候选买/不买、0..1 仓位缩放、已有可卖 lot 的结构化退出意图。
  不用关键词产生交易信号，不恢复 COLD/UNKNOWN/BJSE、不增加标的或资金。
- 模拟与实盘调用同一判断与风控实现，各用自己的账户证据。原始冻结行、
  已持久化 intent、真实/模拟账本、券商安全门和 UNKNOWN 对账语义保持隔离。
- 账户风险以对应账簿有效净值高点为基准：试点 10% 回撤减半新增风险，
  20% 暂停新买并要求复核。这是损失预算而非经验证 alpha。单票既有退出
  阈值、T+1、流动性限制不变；触线不承诺按阈值价格成交。
- 新观点准备完即生成可消费上下文，现有交易任务在合法决策点消费；
  到达迟延不能伪装成盘前已知。结果留来源到判断到消费到执行的回执链。
- 当前判断的执行许可不等于永久规则或自动改参许可；参数/模式升级仍走
  既有研究与授权通道。定时任务使用现有对象，保留原模型与无事静默语义。
- 每周五 20:30 复用现有深度复盘，审视本周和 4/12 周的整体结果、错失
  上涨、资金利用率、成本与回撤。比较 no-KOL/current/challenger，挑战
  上游入口、模式集合和来源相关性；不把逐条观点优化当作整体最优。
- Astra 极高综合分析后主 agent 独立复核；最多三项试验，必须有证伪条件、
  证据要求、负责人、回滚和下次复核。上一期未完成项持续跟踪，不能过了
  12 周就丢弃。短样本、消费次数、工程测试都不是因果盈利证明。
